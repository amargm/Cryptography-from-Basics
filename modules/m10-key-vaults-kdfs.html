Key Vaults & Key Derivation

A 256-bit AES key is a string of 32 random bytes that no human can memorize. How do we turn human passwords into strong keys, and where do we safely store the world's master secrets?

1. The Human Dilemma: Passwords $\neq$ Keys

Humans choose passwords like Coffee2024!. To a computer, that password has almost zero entropy. If a company uses a password directly as an encryption key, a hacker's GPU will crack it in 2 seconds.

To solve this, we use Key Derivation Functions (KDFs). A KDF takes a low-entropy human password and stretches it through intense mathematical loops to produce a high-entropy 256-bit key.

2. Salting: Defeating Rainbow Tables

Hackers have built massive databases called Rainbow Tables containing precomputed hashes for billions of common passwords. If you store plain hashes, they look up the hash in 0.001 seconds!

3. Where Do Secrets Live? Hardware Enclaves

If your private key is stored in your computer's normal RAM, any malicious malware or spyware can read it. To prevent this, modern devices use dedicated physical vaults:

  • TPM (Trusted Platform Module): A physical crypto-chip soldered onto laptop motherboards that secures BitLocker drive encryption keys.
  • Secure Enclaves (Apple & Android): An isolated micro-CPU inside your phone. When you use FaceID, the biometric match happens inside the enclave. Your phone's main operating system never sees the master private key!
  • Hardware Security Modules (HSMs): Multi-thousand-dollar physical appliances used by banks. If an attacker physically drills into the case, the chip detects the pressure change and erases its internal memory instantly.
