1. The Core Mental Model & Command Grammar

Why does OpenSSL feel frustrating? Because it was created over 25 years ago by dozens of independent developers. Some tools expect -in, some expect raw arguments; some output human text, others dump binary. Understanding the Modern OpenSSL 3.x Grammar makes commands predictable without memorization.

The Universal Modern OpenSSL Formula

openssl <VERB/SUBCOMMAND> [ALGORITHM] -in <INPUT_FILE> -out <OUTPUT_FILE> [OPTIONS]

Example: openssl enc -aes-256-gcm -pbkdf2 -in file.txt -out file.enc
1. enc (Encryption)
Symmetric file encryption, decryption, and Base64 transcoding. In OpenSSL 3.x, always use with -pbkdf2 to derive keys securely.
2. dgst (Digests)
Cryptographic hashing (SHA-256, SHA-3) and Keyed HMAC verification over files and byte streams.
3. genpkey & pkey (Keys)
Universal key generation and key inspection. Replaces obsolete algorithm-specific commands (genrsa, rsa, dsaparam).
4. req & x509 (Certificates)
req generates Certificate Signing Requests (CSRs) and self-signed root certs. x509 inspects, parses, and converts certificates.
5. s_client (Network TLS)
Live network client for connecting to remote servers, auditing cipher suites, and downloading live SSL certificate chains.
Golden Rule: -noout
When inspecting keys or certs with -text, always add -noout. Otherwise, OpenSSL dumps the entire Base64 block alongside your text!
Extension Format Type Visual Clue When It Is Used
.pem / .crt ASCII Base64 (Privacy Enhanced Mail) Starts with -----BEGIN CERTIFICATE----- Standard for Linux servers, Nginx, Apache, and Docker.
.der Binary ASN.1 Unreadable binary gibberish in text editors Java keystores, Windows PKI, smartcards, and iOS profiles.
.p12 / .pfx PKCS#12 Archive Password-encrypted binary bundle Bundles private key + server certificate + CA chain into one portable file.

2. Symmetric Encryption & AEAD (openssl enc)

Use symmetric encryption to protect backups, files, and database exports. In OpenSSL 3.x, legacy single-iteration MD5 key derivation has been superseded by PBKDF2.

Encrypt a File with AES-256-GCM (Modern Standard)
AES-256-GCM (AEAD)

Guarantees confidentiality and tampering protection in a single authenticated pass. Prompts interactively for a strong passphrase:

openssl enc -aes-256-gcm -pbkdf2 -iter 100000 -in document.pdf -out document.pdf.enc
-aes-256-gcm
Galois/Counter Mode. Authenticated Encryption with 256-bit key.
-pbkdf2
Mandatory in OpenSSL 3.x. Derives key via standard PBKDF2 instead of vulnerable MD5.
-iter 100000
Forces 100,000 hashing rounds to thwart GPU brute-force cracking.
Decrypt an AES-256-GCM File
Decryption
openssl enc -d -aes-256-gcm -pbkdf2 -iter 100000 -in document.pdf.enc -out document.pdf

Note: If the password is wrong OR if the file was modified by even 1 single bit in transit, OpenSSL prints bad decrypt and drops the payload immediately.

Encrypt with ChaCha20-Poly1305 (Ultra-Fast for ARM & Mobile)
ChaCha20-Poly1305
openssl enc -chacha20-poly1305 -pbkdf2 -iter 100000 -in backup.tar.gz -out backup.enc
Base64 Encode & Decode Raw Data
Encoding Utility
# Encode binary to ASCII: openssl base64 -in image.png -out image.b64 # Decode ASCII back to binary: openssl base64 -d -in image.b64 -out image.png

3. Cryptographic Hashes & HMACs (openssl dgst)

Generate checksums to verify downloads, build tamper-evident audit logs, and compute keyed HMAC tokens.

Compute File Hash (SHA-256 & SHA-3)
One-Way Fingerprints
# Standard SHA-256 Checksum: openssl dgst -sha256 release.iso # High-Security SHA-512 Checksum: openssl dgst -sha512 release.iso # Modern SHA-3 (Keccak) Checksum: openssl dgst -sha3-256 release.iso # Output only the raw hex hash (clean for bash scripting): openssl dgst -sha256 -r release.iso | awk '{print $1}'
Generate Keyed HMAC (API Authentication Token)
HMAC-SHA256

Authenticates that a webhook or payload originated from a trusted partner holding the shared secret key:

openssl dgst -sha256 -hmac "your-secret-api-key" payload.json
Generate Cryptographically Secure Random Keys & Passwords
CSPRNG
# Generate 32 cryptographically random bytes as 64 hex characters (perfect for 256-bit keys): openssl rand -hex 32 # Generate 32 bytes as URL-safe Base64: openssl rand -base64 32

4. Modern Asymmetric Key Management (genpkey & pkey)

Important OpenSSL 3.x Upgrade: The old algorithm-specific tools (genrsa, dsaparam) are deprecated. Use openssl genpkey for all keypair generation.

Generate Ed25519 Keypair (Modern Standard for Signatures)
Ed25519 (Recommended)

Generates tiny 32-byte keys that are completely immune to cache-timing attacks with ultra-fast verification:

# 1. Generate Private Key: openssl genpkey -algorithm ed25519 -out ed25519_key.pem # 2. Extract Matching Public Key: openssl pkey -in ed25519_key.pem -pubout -out ed25519_pub.pem # 3. View Key Details in Plain Text: openssl pkey -in ed25519_key.pem -text -noout
Generate X25519 Keypair (Diffie-Hellman Key Exchange)
X25519 (ECDH)
openssl genpkey -algorithm x25519 -out x25519_key.pem openssl pkey -in x25519_key.pem -pubout -out x25519_pub.pem
Generate RSA-4096 Keypair (Legacy Enterprise Compatibility)
RSA-4096 (Modern Syntax)

Notice the modern genpkey command with -pkeyopt rather than obsolete genrsa:

# Generate unencrypted private key: openssl genpkey -algorithm RSA -pkeyopt rsa_keygen_bits:4096 -out rsa4096_key.pem # Generate password-protected private key (AES-256 encrypted): openssl genpkey -algorithm RSA -pkeyopt rsa_keygen_bits:4096 -aes-256-cbc -out rsa4096_enc.pem # Extract Public Key: openssl pkey -in rsa4096_key.pem -pubout -out rsa4096_pub.pem
Generate NIST ECDSA P-256 / P-384 Keypair
ECDSA (NIST Curves)
openssl genpkey -algorithm EC -pkeyopt ec_paramgen_curve:P-256 -out ecdsa_p256.pem openssl pkey -in ecdsa_p256.pem -pubout -out ecdsa_p256_pub.pem

5. Digital Signatures & Verification (pkeyutl & dgst)

Sign software releases, legal agreements, and audit manifests so anyone can prove they were not modified in transit.

Sign & Verify with Ed25519 (Fastest & Safest)
Ed25519 Signature
# 1. Sign a file (Alice produces document.sig using her private key): openssl pkeyutl -sign -inkey ed25519_key.pem -in contract.pdf -out contract.sig # 2. Verify signature (Bob verifies using Alice's public key): openssl pkeyutl -verify -pubin -inkey ed25519_pub.pem -in contract.pdf -sigfile contract.sig

If valid, OpenSSL prints Signature Verified Successfully. If even 1 byte was altered, it outputs a verification failure.

Sign & Verify with RSA-PSS (Modern RSA Padding)
RSA-PSS (Safe Padding)

Never use old PKCS#1 v1.5 padding for new signatures. Always enforce rsa_padding_mode:pss:

# 1. Sign: openssl dgst -sha256 -sigopt rsa_padding_mode:pss -sign rsa4096_key.pem -out update.sig update.tar.gz # 2. Verify: openssl dgst -sha256 -sigopt rsa_padding_mode:pss -verify rsa4096_pub.pem -signature update.sig update.tar.gz

6. Certificates & PKI (openssl req & x509)

Manage X.509 SSL/TLS certificates, Certificate Signing Requests (CSRs), expiration dates, and CA verification chains.

1-Line Self-Signed HTTPS Certificate (Modern SAN Included)
Self-Signed Dev Cert

Modern web browsers (Chrome, Edge, Safari) reject certificates without a Subject Alternative Name (SAN). This one-liner generates an Ed25519 key and self-signed certificate valid for 1 year with localhost and IP SAN:

openssl req -x509 -newkey ed25519 -keyout server.key -out server.crt -days 365 -nodes \ -subj "/CN=localhost" -addext "subjectAltName=DNS:localhost,IP:127.0.0.1"
-nodes
No DES passphrase on private key; allows Nginx/Node.js to boot automatically.
-addext "subjectAltName=..."
Fulfills modern browser security requirements; prevents "Invalid SAN" red error screens.
Generate CSR (Certificate Signing Request) for Let's Encrypt / DigiCert
Production CSR
openssl req -new -newkey ed25519 -keyout production.key -out production.csr -nodes \ -subj "/CN=example.com" -addext "subjectAltName=DNS:example.com,DNS:www.example.com"
Inspect Any Certificate in Plain English (No Giant Base64 Dump)
x509 Audit
# Dump full readable text (Subject, Issuer, SANs, Validity): openssl x509 -in cert.pem -text -noout # Check Expiration Date only: openssl x509 -in cert.pem -noout -enddate # Check who issued the certificate: openssl x509 -in cert.pem -noout -issuer -subject # Check SHA-256 Fingerprint: openssl x509 -in cert.pem -noout -fingerprint -sha256
Verify Certificate Chain against a Root CA
PKI Verification
openssl verify -CAfile ca_bundle.crt server.crt
Convert Between Certificate Formats (PEM, DER, PKCS#12)
Format Transcoding
# Convert PEM (ASCII) to DER (Binary): openssl x509 -in cert.pem -outform DER -out cert.der # Convert DER (Binary) to PEM (ASCII): openssl x509 -in cert.der -inform DER -out cert.pem # Bundle Private Key + Cert + CA into a PKCS#12 (.pfx / .p12) for Windows / IIS / Java: openssl pkcs12 -export -out bundle.pfx -inkey server.key -in server.crt -certfile ca_chain.crt

7. TLS Auditing & Remote Debugging (openssl s_client)

openssl s_client is the ultimate network diagnostic tool for inspecting remote TLS handshakes, checking negotiated cipher suites, and downloading certificate chains.

Test Live HTTPS Connection with SNI
TLS Diagnostic

Vital: Always pass -servername. Without Server Name Indication (SNI), cloud proxies like Cloudflare or AWS ALB cannot know which virtual host certificate to send you!

openssl s_client -connect example.com:443 -servername example.com
Audit Protocol Versions (Force TLS 1.3 vs Detect Insecure TLS 1.0)
Protocol Audit
# Verify the server accepts modern TLS 1.3: openssl s_client -connect example.com:443 -servername example.com -tls1_3 # Security Audit: Test if server dangerously still supports broken TLS 1.0: openssl s_client -connect example.com:443 -servername example.com -tls1 # (A secure server MUST reject this with a handshake failure!)
Download Remote Server's Full Certificate Chain to Disk
Cert Extraction
openssl s_client -showcerts -connect example.com:443 -servername example.com </dev/null > fullchain.pem
Check HTTP/2 Negotiation (ALPN) & Mail Servers (STARTTLS)
Network Protocols
# Check if server supports HTTP/2 (ALPN protocol negotiation): openssl s_client -connect example.com:443 -servername example.com -alpn h2,http/1.1 </dev/null | grep "ALPN" # Test STARTTLS encrypted session on an SMTP mail server: openssl s_client -connect smtp.gmail.com:587 -starttls smtp

8. The OpenSSL 3.x Migration & Legacy Wall

OpenSSL 3.0 was a monumental release that completely re-architected how cryptographic primitives are loaded. Obsolete ciphers and commands are now sequestered behind the Legacy Provider.

Why Did My Old Script Break in OpenSSL 3.x?

In OpenSSL 3.x, insecure legacy algorithms (RC4, DES, 3DES, Blowfish, CAST, MD2, MD4, MD5) are completely removed from the default provider. If you try to run openssl enc -rc4 or openssl enc -des, OpenSSL throws:

Error setting cipher ... unsupported cipher algorithm

Emergency Recovery Only: To decrypt an ancient archive from 2005, you must explicitly enable the legacy provider alongside default:
openssl enc -provider legacy -provider default -des -d -in old.enc -out old.txt

[No] Deprecated Legacy Command [Yes] Modern OpenSSL 3.x Equivalent Why the Change Was Made
openssl genrsa 2048 openssl genpkey -algorithm RSA -pkeyopt rsa_keygen_bits:4096 Unified key generation architecture; defaults to modern 4096-bit length.
openssl rsa -in key.pem -pubout openssl pkey -in key.pem -pubout Algorithm-agnostic key management for RSA, EC, Ed25519, and X25519.
openssl dsa / dsaparam openssl genpkey -algorithm ed25519 Classical DSA is permanently broken; replaced by Edwards-curve signatures.
openssl rsautl -sign openssl pkeyutl -sign rsautl had dangerous padding vulnerabilities; replaced by safe pkeyutl.
openssl enc -aes-256-cbc (no KDF) openssl enc -aes-256-gcm -pbkdf2 -iter 100000 Old OpenSSL derived keys using 1 round of MD5! PBKDF2 with 100,000 iterations is mandatory.
openssl md5 file.iso openssl dgst -sha256 file.iso MD5 is broken by collision attacks; standalone hash commands deprecated in favor of dgst.
